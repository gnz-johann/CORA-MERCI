# Fase 1 · Bloque 1.0 · Sección 1.0.3 — `HistorialLlamadas.jsx` con contenido equivocado

## Qué se hizo
Se reconstruyó `client/src/pages/HistorialLlamadas.jsx` desde cero. Antes contenía una
copia vieja de una versión primitiva de `Configuracion()` (solo un botón de "Cerrar
sesión") — ni remotamente una pantalla de historial de llamadas. Ahora es una vista real,
con tarjetas de métricas, filtros (fecha, teléfono, estado, agente), tabla paginada, modal
de detalle con transcripción/clasificación IA, y exportar a CSV — todo sobre datos
simulados, como pide explícitamente esta sección del plan.

## Por qué
El informe de Fase 0 encontró este archivo con el contenido incorrecto, y la Sección 1.0.1
de esta misma sesión confirmó que el problema **no era del checkout local** — el archivo
real en `origin/main` tiene exactamente el mismo contenido equivocado. Es un bug real del
repo compartido, no un artefacto de sesión.

## Cómo
Se siguió el mismo patrón visual y de estructura que `Auditoria.jsx` (que sí está bien
construido en este repo): `StatCard` para las métricas, mismos tokens de color
(`#061628`/`#0D2647`/`#155EEF`/etc.), filtros con estado real de React que sí filtran la
tabla, paginación funcional, modal de detalle, y toasts de éxito/error.

Los nombres de campo del mock (`numero_origen`, `numero_destino`, `fecha_inicio`,
`duracion_seg`, `estado`, `resultado`, `clasificacion_ia`, `sentimiento`) se alinearon
contra el modelo real `llamadas` de Prisma y los catálogos `catalogo_estado_llamada`
(En Espera/En Proceso/Finalizada/Cancelada/Transferida/Perdida/Escalada) y
`catalogo_resultado_llamada` (Exitosa/Sin Respuesta/Transferida/Escalada a Humano/Buzón de
Voz/Cancelada por Usuario/Error de Comunicación) — se revisaron en
`merci-platform/prisma/schema.prisma` y `merci-platform/db/merci_schema.sql` antes de
inventar nombres, para que cuando el Bloque 2.3 conecte el backend real, la forma de los
datos ya calce.

**A propósito se dejó en mock** — el plan es explícito: "puede quedar con datos mock por
ahora, se conecta de verdad en el Bloque 2.3". No se creó `llamadas.service.js` ni se llamó
a ningún endpoint.

## Pendiente / riesgos
- Esto es visual + mock, no conectado. El Bloque 2.3 tiene que: crear
  `llamadas.service.js`, conectar esta vista a `GET /api/llamadas`, y agregar en el backend
  lo que el plan ya señalaba que falta ahí (CSV real del lado del servidor y filtro por
  teléfono/agente en la query — hoy el backend según `llamadas.service.js` solo soporta
  `pagina, limite, desde, hasta, estado`).
- El nombre de agente (`agente_nombre`) en el mock es un campo "aplanado" para mostrar en
  la tabla — el modelo real no tiene ese campo directo en `llamadas`, sale de la relación
  con `agentes_virtuales`. Cuando se conecte el backend real, confirmar que el endpoint
  devuelva ese dato ya resuelto (join), no solo el `agente_id`.
- No se probó en un navegador real (no hay forma de levantar el dev server con verificación
  visual en esta sesión) — sí se corrió `npm run build`, que compila limpio.
- **Este commit no se pudo pushear** — ver la Sección 1.0.4 y el resto de esta sesión: el
  push a `origin/feature/bina4-estabilizacion` en `client` falló con 403 (la cuenta de
  GitHub autenticada no tiene permiso de escritura en
  `mariaroman24s-dotcom/merci-platform`). El commit queda listo en la rama local
  `feature/bina4-estabilizacion`, pendiente de subir en cuanto se resuelva el acceso.
