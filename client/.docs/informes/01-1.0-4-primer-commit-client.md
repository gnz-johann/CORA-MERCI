# Fase 1 · Bloque 1.0 · Sección 1.0.4 — Primer commit de `client`

## Qué se hizo
Se creó `feature/bina4-estabilizacion` en `client`, pero **no** con un commit inicial del
estado local como decía el plan al pie de la letra — se descubrió antes de commitear que
`origin/main` (el remoto real, `mariaroman24s-dotcom/merci-platform`) tiene 9+ commits que
el checkout local nunca había descargado. La rama nueva parte de ese `origin/main` real, y
encima se reintegró el trabajo de Bina 4 que sí era genuinamente nuevo (no existía en
`origin/main`): `auditoria.service.js`, `configuracion.service.js`, y la versión de
`Auditoria.jsx` ya conectada a un servicio real (con carga y manejo de error) en vez de la
que trae `origin/main`, que todavía usa datos simulados (`mockAuditoria`).

## Por qué
El plan asumía "el repo del frontend no tiene ningún commit todavía" basándose en el informe
de Fase 0, que a su vez se hizo sobre un checkout local que **nunca se había conectado** al
remoto real. Al hacer `git fetch origin` antes de commitear nada (paso de precaución, no
pedido explícitamente pero necesario dado lo que se estaba por hacer), se confirmó que
`origin/main` no está vacío — tiene páginas completas que no existen en el checkout local
(`Workflows.jsx`, `Automatizaciones.jsx`, `CloudUCM.jsx`, `PreguntasFrecuentes.jsx`,
`Reportes.jsx`) y versiones de `Configuracion.jsx` y `AppRoutes.jsx` distintas a las locales.

Hacer "el commit inicial con el estado local" tal cual estaba habría creado una rama sin
ninguna relación con el trabajo real del equipo, y de haberse fusionado después a `main`
habría podido sobrescribir en silencio el `Configuracion.jsx` real del equipo con la
reconstrucción que se hizo en una sesión anterior sin ese contexto (esa reconstrucción se
hizo porque el archivo local parecía corrupto — una copia de `AppRoutes.jsx` guardada por
error — pero eso era un problema del checkout local, no del repo real). Se preguntó
explícitamente antes de decidir esto — la respuesta fue partir de `origin/main` real.

## Cómo
```bash
cd client
git fetch origin                              # reveló el historial real
git checkout -b local-snapshot-temp            # respaldo del estado local, commit único,
git add -A && git commit -m "..."              #   nunca se pushea — solo por seguridad
git checkout -b feature/bina4-estabilizacion origin/main
git checkout local-snapshot-temp -- src/services/auditoria.service.js
git checkout local-snapshot-temp -- src/services/configuracion.service.js
git checkout local-snapshot-temp -- src/pages/Auditoria.jsx
git checkout local-snapshot-temp -- .docs/informes/INFORME_SITUACION_ACTUAL.md
git checkout local-snapshot-temp -- CLAUDE.md .graphifyignore graphify-out
```
Se corrió `npm run build` después de reconciliar — compila limpio, sin el problema del
import roto de `Workflows` que reportaba la Fase 0 (ese problema **no existe en
`origin/main`** — era otro artefacto del checkout local desactualizado).

**Configuracion.jsx**: se dejó exactamente como está en `origin/main` (su versión real, más
completa, con modal de credenciales PBX) — la reconstrucción local de la sesión anterior
**no** se trajo, por decisión explícita. `configuracion.service.js` sí se trajo (es nuevo,
no pisa nada) como trabajo de base para cuando le toque su turno conectar esa vista, en el
Bloque 2.4.

- `.docs/informes/INFORME_SITUACION_ACTUAL.md` (el informe de Fase 0, ahora sí commiteado)

  anteriores, no existían en `origin/main`)

## Pendiente / riesgos
- La rama `local-snapshot-temp` queda en el repo local (no se pushea, no se pidió). Sirve de
  respaldo por si algo de la reconciliación se hizo mal — se puede borrar cuando el equipo
  confirme que ya no hace falta.
- No se comparó archivo por archivo **todo** lo demás entre el checkout local viejo y
  `origin/main` (solo los archivos relevantes a Bina 4) — es posible que hubiera otro trabajo
  local suelto en páginas de otras binas que esta reconciliación no rescató. Vale la pena que
  cada bina revise si tenía algo local sin commitear que se haya quedado en el checkout viejo
  (que ya no se usa, pero sigue en disco).
- `Configuracion.jsx` de `origin/main` sigue en mock — no se tocó, pero el `Key`/`Eye`/
  `EyeOff` que ya tiene en sus imports sugiere que ya alguien empezó a pensar en la UI de
  credenciales que pide el Bloque 2.4. Revisarlo antes de reconstruir nada ahí.

## Pertenece a otra bina?
No para lo que se tocó (es contenido de Bina 4 sobre una base que ya era del repo real). Sí
vale avisar al equipo en general que el checkout local que se venía usando en sesiones
anteriores estaba desactualizado — cualquier decisión tomada contra ese checkout (incluida
parte del informe de Fase 0) debe releerse con ese contexto.
