# Fase 1 · Bloque 1.2 — Permiso incorrecto de `Sucursales` en `menuSections.js`

## Qué se hizo
Se corrigió `src/data/menuSections.js` línea 44: el ítem `Sucursales` declaraba el permiso
`extensiones.ver` (copiado y pegado por error desde el ítem `Extensiones`). Ahora declara
`sucursales.gestionar`. Con esto se cierra el segundo y último hallazgo del Bloque 1.2 — el
primero (7 rutas sin guard en `AppRoutes.jsx`) ya se había cerrado en el informe
`01-1.2-guards-permiso-vistas.md`.

## Por qué
Antes de este cambio, un usuario con `extensiones.ver` pero sin ningún permiso de
Sucursales veía el ítem "Sucursales" en el menú lateral (porque `menuSections.js` decidía
mostrarlo con el permiso equivocado), aunque no pudiera hacer nada útil al entrar — el
guard real de la ruta y del backend exigen `sucursales.gestionar`, no `extensiones.ver`. Es
un hueco de UX/consistencia, no de seguridad (la ruta y el backend ya estaban bien
protegidos), pero rompía la promesa del proyecto de que las 3 capas (menú, ruta, backend)
usen el mismo string de permiso.

## Cómo
Se verificó el permiso real en las otras dos capas antes de elegir el valor correcto:
- `src/routes/AppRoutes.jsx:126` — `<RutaConPermiso permiso="sucursales.gestionar">`.
- `merci-platform/src/modules/sucursales/sucursales.routes.js` — las 5 rutas (listar,
  obtener, crear, editar, eliminar) usan `requirePermission('sucursales.gestionar')`.
- `merci-platform/db/merci_schema.sql:487-488` — el catálogo de permisos sembrados incluye
  tanto `sucursales.ver` como `sucursales.gestionar`, pero el backend real solo exige
  `gestionar` en las 5 rutas (no diferencia lectura de escritura todavía — eso es el punto
  ya anotado en el plan para el Bloque 2.1, "separar los permisos ver/gestionar").

Con las 3 capas ya alineadas en `sucursales.gestionar`, se corrigió el string en
`menuSections.js` y se corrió `npm run build` — compila limpio.

## Archivos tocados
- `src/data/menuSections.js` (editado — línea 44, permiso de `Sucursales`)

## Pendiente / riesgos
- El backend sigue exigiendo `sucursales.gestionar` para **todo**, incluida la simple
  lectura/listado — un Admin de Sucursal con solo `sucursales.ver` no podría ni listar. Esto
  ya está identificado como tarea propia del Bloque 2.1 ("separar los permisos ver/gestionar
  en Sucursales"), no se toca aquí.
- Con esto, el Bloque 1.2 queda cerrado por completo y la Fase 1 del plan queda completa.

## Pertenece a otra bina?
No — `menuSections.js` es un archivo compartido de navegación, no de una bina específica.
Sucursales es de Bina 1; vale la pena que Bina 1 sepa que el string de permiso ya quedó
unificado en `sucursales.gestionar` en las 3 capas, de cara al trabajo pendiente del
Bloque 2.1.
